# Stage 2A One-Intervention Hazard-Arrest Authority Adapter v0

## Status

Isolated authority adapter implemented and unit-tested; no physical runtime
integration or staged-recovery execution is authorized.

Completed: 2026-08-14

## Purpose

This module implements the smallest authority-enforcing boundary required by
the frozen Stage 2A preflight. It can return one provisional proposal that
reuses `velocity_opposed_thrust_v0`, but it cannot execute the proposal, call a
simulator, bypass Final Veto, select the normal recovery branch, or grant active
authority to the staged FSM.

## API

`request_hazard_arrest_proposal(session, authority, evidence)` is a pure call.
It returns an immutable updated session and an immutable decision. Authority is
disabled when the authority input is absent. A proposal requires an explicitly
enabled and granted request for `hazard_arrest`, separately authorized trigger
evidence, and available valid state, instrumentation, recovery-evaluation, and
hazard evidence.

`consume_hazard_arrest_proposal(session, proposal)` marks the one proposal as
consumed in a new immutable session. It does not submit the action to Final
Veto or execute physics. A second proposal is blocked both before and after
consumption.

## Evidence Boundary

The adapter preserves raw realized and predicted speed ratios and an explicit
evidence status. It does not derive active authority by comparing either ratio
with `1.90`. The external authority input must separately state that the hazard
evidence has been authorized for this request. Missing, invalid, and
unsupported evidence remain distinct blocking outcomes.

Realized overspeed remains an existing adverse terminal condition rather than
an intervention entry. Explicit abort remains terminal evidence and never
becomes a physical action.

## Action Boundary

The provisional action is generated by the existing
`generate_velocity_opposed_action` helper and retains the branch identity
`velocity_opposed_thrust_v0`. The proposal records:

- `final_veto_evaluation_required = true`;
- `final_veto_bypass_allowed = false`;
- `adapter_executes_action = false`;
- `shadow_output_consumed_by_physical_runtime = false`.

The adapter neither imports a runner nor invokes a transition function. Future
runner integration must remain separately reviewed.

## Authority Scope

Only a request explicitly scoped to `hazard_arrest` can produce a proposal.
`stabilization_assessment`, `radial_recommitment`, `tangential_alignment`,
`crossing_preparation`, `recoverability_verification`, `nominal_handoff`,
`retreat`, and `explicit_abort` cannot produce an action through this adapter.

Release and handoff behavior remain `not_implemented`. Staged recovery
execution remains `not_authorized`.

## Scientific Boundary

This adapter is implementation infrastructure, not an active controller or a
validated hazard policy. It does not validate an entry threshold, release
condition, intervention efficacy, recovery improvement, controller safety,
handoff readiness, or deployment readiness. No measured Stage 2A experiment
was run while implementing it.
